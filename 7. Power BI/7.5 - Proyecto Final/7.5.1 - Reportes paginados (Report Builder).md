## Introducción

Los informes interactivos de Power BI Desktop que hemos construido durante este bloque son perfectos para exploración y análisis: el usuario filtra, drilla, cambia de perspectiva. Pero hay escenarios donde esto no es lo que se necesita.

El departamento financiero de HotelesMediterraneum necesita un informe mensual de revenue por hotel en formato PDF de 40 páginas, una por hotel, con el logo corporativo en el encabezado, la fecha de impresión en el pie de página y cada hotel exactamente en su propia página, sin que los datos se corten. El director general quiere el mismo informe en Excel con totales por país. Ninguno de estos requisitos puede cumplirse correctamente con un informe interactivo de Power BI Desktop.

Para estos casos existe **Power BI Report Builder**: la herramienta de reportes paginados. Los reportes paginados están diseñados para imprimirse o exportarse de forma precisa, con control total sobre la paginación, el diseño y el formato de cada celda.

### Objetivos de la sesión

- Entender la diferencia entre informes interactivos y reportes paginados.
- Instalar y configurar Power BI Report Builder.
- Conectar Report Builder al modelo semántico de HotelesMediterraneum en el Service.
- Crear un informe tabular con agrupaciones, subtotales y totales generales.
- Añadir parámetros para que el usuario filtre el informe antes de renderizarlo.
- Publicar el reporte paginado en Power BI Service y configurar su exportación.

### Prerequisitos

- `HotelesMediterraneum_7.4.7_resuelto.pbix` publicado en el workspace de producción.
- Power BI Report Builder instalado (descarga gratuita desde Microsoft Download Center).
- Cuenta con licencia Power BI Pro o PPU.

## 1. Reportes paginados vs informes interactivos

| Característica | Informe interactivo (Desktop) | Reporte paginado (Report Builder) |
|---|---|---|
| Interactividad | Alta (filtros, drill, slicers) | Baja (parámetros fijos al renderizar) |
| Paginación | Automática, no controlable | Controlada al píxel |
| Exportación | PDF básico, sin control de páginas | PDF, Excel, Word, CSV con formato completo |
| Tablas largas | Se desplazan (scroll) | Se pagina a nuevas páginas automáticamente |
| Encabezados/pies de página | No disponibles | Configurables por página |
| Orientación | Solo horizontal (landscape) | Horizontal o vertical por sección |
| Caso de uso | Exploración y análisis | Facturación, informes regulatorios, listados |

## 2. Instalación de Power BI Report Builder

Power BI Report Builder es una aplicación de escritorio independiente de Power BI Desktop. Se descarga desde el Microsoft Download Center buscando "Power BI Report Builder".

Una vez instalado, se abre como una aplicación separada. La interfaz es similar a SSRS (SQL Server Reporting Services) del que deriva histórica y técnicamente.

### 2.1 Interfaz de Report Builder


## 3. Conectar al modelo semántico de Power BI Service

### 3.1 Crear una fuente de datos

En Report Builder: **Insert > Data source** → **New**. En el diálogo:
- **Name**: `HotelesMediterraneum`
- **Connection type**: `Microsoft Power BI Dataset`
- **Connection string**: el endpoint DAX del modelo semántico (formato XMLA).

El endpoint XMLA se obtiene en Power BI Service: en el workspace, junto al modelo semántico → **Settings > Premium** → copiar el **Workspace connection**. El endpoint tiene el formato:
```
powerbi://api.powerbi.com/v1.0/myorg/HotelesMediterraneum - Producción
```

Añadir el nombre del dataset al final:
```
powerbi://api.powerbi.com/v1.0/myorg/HotelesMediterraneum - Producción;initial catalog=HotelesMediterraneum_7.4.7_resuelto
```

Pulsar **Test Connection** para verificar la conexión. Si la autenticación falla, usar **Set credentials** e introducir las credenciales de la cuenta con acceso al workspace.

> [CAPTURA 3.1 — Diálogo de fuente de datos con el tipo "Microsoft Power BI Dataset" seleccionado. La cadena de conexión XMLA introducida en el campo correspondiente. El botón "Test Connection" y el resultado "Connection created successfully" visible.]

### 3.2 Crear un dataset

Un dataset en Report Builder es una consulta DAX que extrae datos del modelo semántico. A diferencia de Power BI Desktop donde el lenguaje nativo es DAX de medidas, aquí las consultas se escriben en **DAX de consulta** (sintaxis similar a SQL pero con funciones DAX).

**Insert > Dataset** → **New**. En el diálogo, seleccionar la fuente de datos `HotelesMediterraneum` y escribir la consulta.

Consulta para el informe de revenue mensual por hotel:

```dax
EVALUATE
SUMMARIZECOLUMNS(
    dim_hotel[hotel_nombre],
    dim_hotel[country],
    dim_fecha[año],
    dim_fecha[mes_nombre],
    dim_fecha[mes_num],
    "Revenue Total", [Revenue Total],
    "ADR", [ADR],
    "Occupancy Rate", [Occupancy Rate],
    "Num Reservas", [Num Reservas]
)
ORDER BY
    dim_hotel[country],
    dim_hotel[hotel_nombre],
    dim_fecha[año],
    dim_fecha[mes_num]
```

> [CAPTURA 3.2 — Diálogo de dataset con la consulta DAX introducida en el editor. El panel de resultados debajo muestra una vista previa de los datos con columnas hotel_nombre, country, año, mes_nombre, Revenue Total, ADR, Occupancy Rate, Num Reservas.]

## 4. Crear la tabla principal (Tablix)

El elemento principal de los reportes paginados es el **Tablix**: una estructura de tabla flexible que combina filas, columnas y grupos de forma anidada.

### 4.1 Insertar una tabla

**Insert > Table > Table Wizard**. El asistente guía a través de la configuración:

1. Seleccionar el dataset `HotelesMediterraneum`.
2. Arrastrar campos a las áreas:
   - **Row groups**: `country`, `hotel_nombre` (dos niveles de agrupación).
   - **Column groups**: vacío (tabla sin grupos de columna, para este informe).
   - **Values**: `Revenue Total`, `ADR`, `Occupancy Rate`, `Num Reservas`.
3. Activar **Show subtotals and grand totals**.
4. Seleccionar un estilo visual predefinido o dejarlo sin estilo para aplicar formato manual.

Pulsar **Finish**. El asistente genera la estructura del Tablix en el canvas.

### 4.2 Estructura del Tablix resultante

```

Spain              Hotel Barcelona  1.234.567        142     78%         4.521

                   Hotel Ibiza      1.456.789        165     82%         5.123
                   Subtotal Spain   3.678.788                            13.535
Italy              Hotel Roma       876.543          125     71%         3.456
                   ...
                   Subtotal Italy   ...
Greece             ...
                   Subtotal Greece  ...
Grand total        ...
```

### 4.3 Formato de celdas

En cada celda del Tablix puedes aplicar formato directamente. Seleccionar una celda → **Properties** panel:
- **Format**: código de formato de número. Para revenue: `#,##0 €`. Para porcentaje: `0.0%`.
- **Font**: tamaño y estilo.
- **BackgroundColor**: expresión de formato condicional.
- **TextAlign**: alineación del texto dentro de la celda.

## 5. Parámetros del informe

Los parámetros permiten al usuario configurar el informe antes de renderizarlo. A diferencia de los slicers del informe interactivo (que filtran en tiempo real), los parámetros de un reporte paginado se configuran en un formulario previo al renderizado y afectan a la consulta DAX que extrae los datos.

### 5.1 Crear un parámetro

**Insert > Parameter** → **New**. En el diálogo:
- **Name**: `PaisSeleccionado`
- **Data type**: Text
- **Prompt**: "Selecciona el país:"
- **Allow blank**: desactivado.
- **Available values**: lista manual (Spain, Italy, Greece) o consulta a dataset.
- **Default values**: Spain.

### 5.2 Vincular el parámetro a la consulta DAX

Modificar la consulta DAX del dataset para incluir el filtro del parámetro:

```dax
EVALUATE
CALCULATETABLE(
    SUMMARIZECOLUMNS(
        dim_hotel[hotel_nombre],
        dim_hotel[country],
        dim_fecha[año],
        dim_fecha[mes_nombre],
        dim_fecha[mes_num],
        "Revenue Total", [Revenue Total],
        "ADR", [ADR],
        "Occupancy Rate", [Occupancy Rate],
        "Num Reservas", [Num Reservas]
    ),
    dim_hotel[country] = @PaisSeleccionado
)
ORDER BY
    dim_hotel[hotel_nombre],
    dim_fecha[año],
    dim_fecha[mes_num]
```

El `@PaisSeleccionado` hace referencia al parámetro creado. Cuando el usuario introduce o selecciona un valor en el formulario, la consulta se ejecuta con ese valor.

> [CAPTURA 5.1 — Preview del informe en Report Builder. En la parte superior aparece el formulario de parámetros con el selector "Selecciona el país:" con "Spain" seleccionado y el botón "View Report". Debajo, el Tablix muestra solo los datos de Spain.]

## 6. Encabezado y pie de página

Los reportes paginados tienen zonas de encabezado y pie de página que se repiten en cada página impresa.

### 6.1 Activar encabezado y pie de página

**Insert > Header** / **Insert > Footer**. Las zonas aparecen arriba y abajo del canvas. Pueden contener texto, imágenes y expresiones dinámicas.

### 6.2 Expresiones dinámicas en el pie de página

En el pie de página, puedes añadir expresiones que se evalúan en el momento de renderizar el informe:

- Número de página actual: `=Globals!PageNumber`
- Número total de páginas: `=Globals!TotalPages`
- Fecha y hora de ejecución: `=Format(Globals!ExecutionTime, "dd/MM/yyyy HH:mm")`
- Nombre del parámetro seleccionado: `=Parameters!PaisSeleccionado.Value`

Para HotelesMediterraneum, el pie de página muestra:
```
Informe generado el 15/06/2025 09:32  |  País: Spain  |  Página 3 de 12
```

### 6.3 Logo en el encabezado

**Insert > Image** en la zona del encabezado. Seleccionar la imagen del logo corporativo. La imagen se incrusta en el archivo .rdl del informe.

## 7. Publicar en Power BI Service y exportar

### 7.1 Guardar el informe

El archivo se guarda como `.rdl` (Report Definition Language, el formato estándar de SSRS). **File > Save as**.

### 7.2 Publicar en Power BI Service

**Home > Publish**. Seleccionar el workspace **HotelesMediterraneum - Producción**. El reporte aparece en el workspace con el icono de reporte paginado (diferente al icono del informe interactivo).

### 7.3 Formatos de exportación

En Power BI Service, al abrir el reporte paginado, el usuario ve el formulario de parámetros. Tras configurarlos y renderizar el informe, puede exportarlo desde el menú **Export**:
- **PDF**: con paginación exacta, encabezados y pies de página, logos.
- **Excel**: datos en formato de tabla con formato de celda. Subtotales y totales incluidos.
- **Word**: tabla formateada en documento Word.
- **CSV**: solo los datos, sin formato.
- **MHTML**: formato web embebible.
- **TIFF**: imagen de cada página (útil para archivar).
- **XML**: datos estructurados.

> [CAPTURA 7.1 — Power BI Service con el reporte paginado abierto. El menú de exportación desplegado muestra los formatos disponibles. El formulario de parámetros en la parte superior muestra "País: Spain" y "Período: 2025".]

## 8. Errores comunes

**"No aparece la opción 'Microsoft Power BI Dataset' en los tipos de conexión de Report Builder."**
Verificar que la versión instalada de Power BI Report Builder es reciente (2021 o posterior). Las versiones antiguas no incluyen el conector de Power BI Dataset. Descargar la versión más reciente desde el Microsoft Download Center.

**"La conexión XMLA da error de autenticación."**
El endpoint XMLA solo está disponible en workspaces con capacidad Premium o Premium Per User (PPU). Si el workspace es de capacidad compartida (Pro), no tiene endpoint XMLA y no se puede conectar desde Report Builder. Verificar el tipo de licencia del workspace.

**"El informe renderiza datos de todos los países aunque haya configurado el parámetro."**
Verificar que el parámetro en la consulta DAX usa exactamente el mismo nombre que el parámetro creado en Report Builder (`@PaisSeleccionado`), y que el valor del parámetro en la consulta DAX tiene el tipo correcto (texto entre comillas si es texto).

**"El PDF exportado corta los datos a mitad de una fila en algunas páginas."**
Configurar el Tablix para que no se permita saltos de página dentro de un grupo: en las propiedades del grupo (clic derecho en el grupo en el panel de datos del Tablix) → **Group properties > Page breaks > Keep together on one page if possible**.

**"El reporte tarda mucho en renderizarse en el Service."**
La consulta DAX en Report Builder se ejecuta cada vez que se renderiza el informe. Si la consulta es compleja o el modelo es grande, el tiempo de renderizado puede ser alto. Optimizar la consulta (reducir el número de columnas, añadir filtros de parámetros para limitar los datos) o usar una vista materializada en el modelo.

## 9. Ampliación opcional

### Extra 1: Subreportes

Report Builder permite insertar un subreporte (un archivo .rdl secundario) dentro del reporte principal. El subreporte recibe parámetros del reporte padre. Útil para mostrar una tabla de detalle dentro de cada fila de agrupación del reporte principal.

### Extra 2: Suscripciones de correo electrónico

En Power BI Service, los reportes paginados admiten **suscripciones por email**: el sistema envía automáticamente el reporte renderizado como adjunto (PDF, Excel, etc.) a una lista de destinatarios en un horario programado. Por ejemplo, el informe financiero mensual se envía automáticamente el primer día de cada mes en PDF a los directores de área.

### Extra 3: Reportes paginados como solución de facturación

Con Report Builder es posible construir facturas individualizadas: un reporte por cliente, con el logo y los datos del cliente, generado automáticamente desde el modelo semántico. Combinando parámetros con suscripciones de correo, cada cliente puede recibir su factura personalizada sin intervención manual.
